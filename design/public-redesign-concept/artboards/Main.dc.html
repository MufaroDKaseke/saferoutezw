Step 1 · Inspect the live site

What the current public site does today

Chrome captures of the running app at localhost:3000, desktop 1440px plus one narrow capture. All seven reachable public routes returned 200. The alert detail route could not be opened: the local API returns zero published alerts, so there was no alert to click.

Tablet (768px) and interactive states were not captured. Findings marked as observed come from these screenshots; the rest is stated as a limitation.

Preserve

  • Accessible forms, visible labels and 44px+ inputs
  • Clear “published, human-reviewed” safety messaging
  • Server-rendered pages, no login, low-data List mode on the map
  • “No alert does not mean the road is safe” wording
  • OTP verification, consent and non-enumerating manage flow

Problem → proposed change

  • Generic white cards, no identityForest-green brand, route-line motif, warm paper ground
  • Planner is not the heroSplit hero: journey planner left, schematic map right
  • Severity not visibleFour severity badges: colour + icon + word, shape differs
  • Header crowds on phonesLogo, compact Get alerts, menu drawer
  • Filters eat the screenSearch first, filters collapse into a sheet on phones
  • “Operators” unclearRenamed “Transport Operators”, with a plain-language intro
  • Thin empty / error statesIllustrated, explain why, offer a next step
